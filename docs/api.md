# Developer API

Install from a checkout using `python -m pip install .`. Use Python 3.12 for the validated
ML environment. The public imports below are available from `open_stair`.

## Documents and annotations

```python
from open_stair import Corpus, load_document, parse_markdown

book = load_document("manual.md", document_id="manual")
# For content already in memory:
book = parse_markdown("# Manual\n## Replication\nSetup instructions...", "manual")
print(book.toc())
for section in book.leaves:
    print(section.id, section.label, section.path, section.text)

corpus = Corpus({book.id: book})
corpus.save("artifacts/manual.json")
restored = Corpus.load("artifacts/manual.json")
```

`load_document(path, document_id=None)` supports Markdown/plain text and PDF with the PDF
extra installed. `parse_markdown(text, document_id, source="", title=None)` constructs the
same document type. IDs are annotation/provenance metadata; model targets are numbered
section names. `open-stair inspect --corpus ...` prints both IDs and labels.

Queries use one JSON object per line:

```json
{"query":"How do I configure replication?","document_id":"manual","split":"train","section_path":["Manual","Replication"]}
{"query":"Where are replication settings?","document_id":"manual","split":"dev","section_path":["Manual","Replication"]}
{"query":"What are the replication setup steps?","document_id":"manual","split":"test","section_path":["Manual","Replication"]}
```

Supply exactly one target key: `section_id`, unambiguous `section_path`, or `section_ids`.
Multiple relevant IDs are supported by evaluation; training requires one target per question.
Train/dev/test are explicit. Duplicate normalized questions cannot cross splits.

## Fit and load

```python
from open_stair import STAIR, TrainConfig

config = TrainConfig()  # Published STAIR model-training settings by default.
model = STAIR.fit(book, "annotations.jsonl", "runs/manual", config=config)
model = STAIR.from_pretrained("runs/manual", device="auto")
hits = model.search("How do I configure replication?", k=3)
```

`STAIR.fit(document, queries, output_dir, *, model_name=..., config=None)` prepares separate
train/dev data, runs gradient updates, saves the checkpoint with the best dev Recall@1, and
returns that selected model. The output directory must be new or empty. Dev data is required.
One document is trained per model. The default base model is Mistral-7B-Instruct-v0.2.

`TrainConfig` supports maximum epochs/patience, separate input/output token limits, LoRA
rank/alpha/dropout/module selector, learning rate, batch/accumulation size, seed, device,
dtype, and gradient checkpointing. `TrainConfig.from_dict(settings)` rejects unknown keys.
`lora_rank=0` opts into full fine-tuning. Custom models/sizes are configurable variants;
they do not reproduce the paper's default Mistral experiment.

`STAIR.from_pretrained(path, *, device="auto")` loads the tokenizer, weight artifact,
document/ToC snapshot, and manifest. Device choices are `auto`, `cpu`, `cuda`, and `mps`.
Adapter runs need their original base model; merged exports are standalone. Loading remote
model IDs may download weights. No remote model Python code is executed by these loaders.

## Search results

`search(query, k=3, document_id=None) -> list[SearchResult]` returns ranked leaves with:

| Field | Meaning |
| --- | --- |
| `document_id`, `section_id` | Stable source/annotation identifiers |
| `section_label` | Numbered ToC leaf name generated by the model |
| `title`, `path` | Original heading and ancestry |
| `source`, `line`, `page` | Source path and available location metadata |
| `text` | Source text for the retrieved leaf |
| `score` | Beam sequence log score, not a confidence probability |
| `backend` | `neural` for STAIR; `bm25` only for the explicit baseline |

`hit.to_dict()` returns a JSON-serializable mapping. Neural results are constrained to valid
leaf names. This does not guarantee relevance or factual answers. The library retrieves
sections rather than synthesizing an answer, and no lexical fallback is used.

## Export learned weights

```python
model.save_pretrained("runs/manual-copy")
model.save_pretrained("runs/manual-standalone", merge_adapter=True)
reloaded = STAIR.from_pretrained("runs/manual-standalone")
```

`merge_adapter=True` merges LoRA deltas into the base model and changes this loaded object's
model to its merged form. The export contains standard Hugging Face safetensors/config/tokenizer
files plus STAIR metadata. Choose a new/empty directory; existing nonempty output is rejected.
Corpus snapshots and learned weights can retain source data; distribute them only with the
appropriate rights. Export does not apply a new license to the base model or its data.

## Question generation and evaluation

```python
from open_stair.questions import generate_queries, LocalQuestionGenerator
from open_stair.data import load_queries, write_jsonl
from open_stair.evaluation import evaluate

rows = generate_queries(book, LocalQuestionGenerator())
write_jsonl("annotations.jsonl", rows)

resolved = load_queries("annotations.jsonl", Corpus({book.id: book}))
report = evaluate(model, Corpus({book.id: book}), resolved, k=3, split="test")
```

`LocalQuestionGenerator` defaults to Mixtral-8x7B-Instruct-v0.1 and needs substantial memory.
Alternatively pass any callable `generator(paragraph: str, count: int) -> list[str]` to
`generate_queries`. Question quality and semantic split leakage require review. Evaluation
reports macro Recall@1/k, MRR@k, nDCG@k, invalid-section rate, and per-query predictions.

## Errors and artifact compatibility

Invalid splits/targets/configuration, corpus/model mismatch, and token-limit overflow raise
`ValueError`. Missing source/model files raise `OSError`. Model/runtime failures can also
propagate from PyTorch, Transformers, and PEFT; inspect those errors for memory or model
compatibility issues. CLI input errors use exit status 2. The model manifest and corpus
schemas are versioned. Pre-0.2 models require retraining because their label format differs.
